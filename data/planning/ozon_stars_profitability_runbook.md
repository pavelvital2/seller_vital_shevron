# Ozon «Звёздные товары»: контроль прибыльности

Дата проверки: 2026-07-29.

## Итог

`Звёздные товары` — платная программа продвижения Ozon. Для Vital Shevron
текущая комиссия составляет `1,5%` от всего реализованного оборота.

Оценивать программу только по обороту пользователей программы нельзя: ЛК не
показывает, сколько таких покупок не произошло бы без услуги. Основной критерий
— требуемый прирост прибыли и контролируемое сравнение с периодом без
программы.

## Подтверждённая механика

Источник: ЛК Vital Shevron:

```text
Продвижение -> Лояльность -> Звёздные товары
https://seller.ozon.ru/app/loyalty/sellerpoints
```

Подтверждено:

- программа подключена `24.11.2025`;
- текущая комиссия — `1,5%` от всего оборота;
- участвуют все прошедшие модерацию товары, доступные для покупки;
- товары получают специальные размещения и способы оплаты через Ozon Банк;
- после отключения комиссия перестаёт начисляться сразу;
- размещения могут сохраняться до 24 часов после отключения без комиссии.

В Ozon Seller API списание приходит как:

```text
operation_type = StarsMembership
operation_type_name = Звёздные товары
```

Строка списания связывается с завершённой продажей
`OperationAgentDeliveredToCustomer` по `posting_number + sku`.

## Порог окупаемости

Основной фактический расчёт:

```text
прибыль после услуги =
  выплата Ozon - себестоимость физических изделий

требуемый прирост продаж =
  списание StarsMembership / прибыль после услуги
```

Расчёт предполагает сохранение текущего среднего товарного состава. Отдельно
показывается:

- фактический full-cost сценарий;
- целевая маржа владельца;
- щедрый sensitivity-сценарий без распределения рекламы и хранения на
  дополнительные продажи.

Даже в щедром сценарии оборот пользователей программы нельзя считать целиком
новым. Отчёт должен показывать, какая доля этого оборота обязана быть полностью
добавочной для окупаемости.

## Контрольное отключение

Отключение — marketplace write. Порядок:

```text
read-only отчёт -> owner review -> explicit approval ->
fresh LK preflight -> отключение -> verify -> 14-дневный контроль
```

На время теста по возможности не менять массово цены, рекламу и остатки.
Сравнивать одинаковые дни недели по:

- выкупленным товарам;
- физическим изделиям по `pack_qty`;
- обороту завершённых выкупов;
- прибыли после расходов и себестоимости;
- возвратам и наличию.

Если снижение выкупов меньше рассчитанного порога окупаемости, программу не
подключать обратно.

## Подтверждённое отключение 2026-07-29

Owner-approved отключение выполнено через штатный LK endpoint:

```text
POST /api/starlight/deactivate
reason = REASON_TEMPORARILY_DEACTIVATING
```

Safety-проверка ограничила write одним запросом точного аккаунта
`Vital Shevron`. Результат:

- HTTP `200`;
- `isActive: true -> false`;
- `welcome bonuses` до операции были неактивны;
- цены, акции, реклама, карточки и медиа не изменялись;
- финальный экран ЛК подтвердил прекращение продвижения;
- повторное подключение осталось доступно, но не выполнялось.

Apply:

```text
data/runs/2026-07-29/ozon_stars_deactivate_apply_20260729T1700/
```

Контрольные one-shot timers назначаются на `24 часа`, `3`, `7` и `14` полных
дней. Финансовые списания проверять по `posting.order_date`: после отключения
ещё могут появляться операции по старым заказам, завершённым позднее.

## Восстановление после Seller API 429

Контроль `7` дней 2026-08-06 был поставлен одновременно с ежедневным
liquidation-контролем в `09:00 МСК`. Stars начал работу через две секунды после
него и получил исчерпанный лимит Ozon Seller API `2 запроса/с` на
`POST /v1/analytics/data`; штатных коротких HTTP-повторов оказалось
недостаточно. Какой именно соседний запрос исчерпал последний слот, отдельно
не подтверждено, поэтому исправлены и расписание, и внутренняя серия чтений.

Для read-only `ozon-stars-control` действует отдельное восстановление:

- повторять только операцию чтения, завершившуюся явным `HTTP 429`;
- паузы между повторами: `5`, `10`, `20` секунд;
- ошибки других типов автоматически не повторять;
- выдерживать одну секунду между текущим отчётом, baseline и отдельной
  финансовой сверкой StarsMembership;
- будущие one-shot Stars-контроли запускать в `09:15 МСК`, отдельно от
  ежедневного liquidation-контроля в `09:00 МСК`;
- повторный запуск оформлять новым read-only Job Worker job, не изменяя
  состояние программы Stars и другие параметры магазина.

Финансовая сверка `/v3/finance/transaction/list` принимает полный protobuf
timestamp. Для периода передавать начало как `YYYY-MM-DDT00:00:00.000Z`, конец
как `YYYY-MM-DDT23:59:59.999Z`; дата без времени приводит к `HTTP 400` и не
должна повторяться как rate-limit ошибка.

## Контроль 24 часа 2026-07-30

Read-only проверка подтвердила один спорный хвост:

- заказ создан `2026-07-29 16:37:50 UTC`, через `2 ч 41 мин` после
  подтвержденного отключения;
- завершенная реализация `650 руб.`;
- `StarsMembership` `9,75 руб.`, то есть ровно `1,5%`;
- заказов, созданных после полных 24 часов и уже завершенных к моменту
  проверки, не было.

Не считать сам факт поздней финансовой операции доказательством повторного
подключения: сначала разделять строки по `posting.order_date`. Но комиссию по
заказу, созданному уже после деактивации, считать спорной и повторно проверять
после финансового дозревания. Живой `isActive` проверять отдельно; активный
CDP/keeper не заменяет проверку авторизации и статуса программы.

Артефакт:

```text
data/runs/2026-07-30/ozon_stars_24h_control_20260730T1814/
```
