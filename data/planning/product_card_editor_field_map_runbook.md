# Product Card Editor Field Map Runbook

Дата создания: 2026-06-28

## Назначение

Это рабочая карта полей редакторов Ozon/WB для ассортимента Vital Shevron:
шевроны, нашивки, петлицы и комплекты из них в категории/предмете `Декор для
одежды`.

Карта нужна для карточных аудитов, master passport и будущих dry-run. Она не
является разрешением на изменение карточек. Любое изменение карточек,
характеристик, фото, группировки, названий или описаний выполняется только по
цепочке:

```text
read-only -> dry-run -> review -> approved -> apply -> verify -> result
```

Если категория/предмет карточки изменятся или маркетплейс поменяет редактор,
карту нужно обновить перед массовым dry-run.

## Главное правило

В HTML-аудитах и таблицах для владельца показывать только поля, относящиеся к
шевронам, нашивкам, петлицам и комплектам в текущей категории. Нельзя
подтягивать широкий список WB/Ozon-параметров из чужих предметов вроде сумок,
головных уборов, подсумков и других не относящихся к карточке товаров.

Каждый целевой параметр показывать в формате:

```text
поле -> сейчас -> рекомендую -> почему/статус
```

## Ozon: поля редактора

### General info

- `name` / `Название` - единое название до `60` символов:
  тип изделия + способ крепления + тематика/структура + место ношения.
- `descriptionCategoryId` / `Категория и тип` - не менять пачками без
  отдельного review.
- `barcode` / `Штрихкод` - не менять.
- `offerId` / `Артикул` - опасное поле. По умолчанию не менять в обычном
  SEO/контентном dry-run. Менять только если в owner-approved пакете или
  отдельном подтверждении владельца явно указано, что артикул продавца тоже
  под замену. Подтвержденный маршрут 2026-06-28: Ozon Seller API
  `/v1/product/update/offer-id`, verify через `product_id` и факт, что в
  карточке `offer_id` стал равен внутреннему артикулу.
- `depth`, `width`, `height` / габариты упаковки, мм - заполнять по правилу
  упаковки.
- `weight` / вес с упаковкой, г - заполнять по правилу веса. Для обычного
  шеврона, нашивки и товарной единицы петлиц текущий минимальный рабочий вес -
  `10 г`; меньшее значение считать рассинхроном без отдельного
  owner-approved исключения.

### Характеристики

- `85` / `Бренд` - `VitalEmb`.
- `9048` / `Название модели (для объединения в одну карточку)` - ключ
  модели/группы; точную группировку согласовывать отдельно.
- `22232` / `ТН ВЭД коды ЕАЭС` -
  `5810999000 - Прочие вышивки из прочих текстильных материалов`.
- `23171` / `#Хештеги` - до `30` релевантных хештегов из SEO query pack и
  таблицы частотности; `БПЛА` не использовать как Ozon-хештег.
- `4191` / `Аннотация` - единое описание до `2000` символов, три блока:
  товар; материал/качество; магазин.
- `7405` / `Материал` - `Габардин`.
- `4382` / `Размеры, мм` - размер изделия `ширина*высота мм`.
- `8513` / `Количество в упаковке, шт` - количество физических изделий:
  `1`, `2`, `3`, `4`, `5`; петлицы = `1` как одна неразрезанная пара.
- `8962` / `Единиц в одном товаре` - то же количество физических изделий;
  для петлиц = `1`.
- `10096` / `Цвет товара` - все цвета изделия по убыванию площади заполнения.
- `10097` / `Название цвета` - короткое название варианта/шеврона для
  группировки.
- `9390` / `Целевая аудитория` - `Взрослая`.
- `22270` / `Вид выпуска товара` - `Фабричное производство`.
- `4389` / `Страна-изготовитель` - `Россия`.
- `11650` / `Количество заводских упаковок` - рабочая рекомендация `1`, но
  перед apply подтвердить dry-run.
- `23536` / `Нужен код маркировки` - для всех текущих изделий Vital Shevron
  маркировка не требуется; целевое значение `false`. Если Ozon показывает
  пустое значение или не дает пройти verify без этого поля, отправлять
  `false` и проверять факт через `/v4/product/info/attributes`.

### Ozon: не заполнять без отдельного review

- `23249` / `Количество товара в УЕИ` - назначение для нашей категории не
  подтверждено.
- `23518` / `Минимальное количество оптом` - только при отдельной оптовой
  логике.
- `22390` / `Объединить в похожие товары` - отдельный review группировки,
  не применять вместе с SEO/атрибутами автоматически.
- `9070` / `Признак 18+` - для обычных шевронов не заполнять/false; менять
  только если товар действительно 18+.

## WB: поля редактора

Предмет: `Декор для одежды`.

Подтвержденная логика вариаций в редакторе:

- объединяющая характеристика: `Бренд`;
- меняющиеся характеристики: `Цвет`, `Количество предметов в упаковке`.

### Основная информация и характеристики

- `15000000` / `Наименование` - единое название до `60` символов.
- `category` / `Категория продавца` - `Декор для одежды`, не менять пачками.
- `isAdult` / `18+` - false/unchecked для обычных карточек.
- `vendorCode` / `Артикул продавца` - опасное поле. По умолчанию не менять в
  обычном SEO/контентном dry-run. Менять только если в owner-approved пакете
  или отдельном подтверждении владельца явно указано, что артикул продавца
  тоже под замену. Подтвержденный маршрут 2026-06-28 для существующей карточки:
  WB Content API `/content/v2/cards/update` с сохранением текущего `nmID`,
  размеров, характеристик и `sizes`; verify поиском карточки по новому
  `vendorCode`.
- `nmID` / `Артикул WB` - не менять.
- `brand` / `Бренд` - `VitalEmb`.
- `14177449` / `Цвет` - все цвета изделия по убыванию площади заполнения.
- `15000001` / `ТНВЭД` - `5810999000`.
- `needKiz`, `kizMarked` / маркировка КИЗ - false/unchecked.
- `14177452` / `Описание` - единое описание до `2000` символов, три блока.
- `14177453` / `Баркоды` - не менять.
- `dimensions.length`, `dimensions.width`, `dimensions.height` - упаковка в
  сантиметрах по правилу упаковки.
- `dimensions.weightBrutto` - вес с упаковкой в килограммах.
- `384944` / `Вид декора для одежды` - `шеврон`, `нашивка` или `петлица` по
  типу товара.
- `14177450` / `Состав`:
  - для шевронов и петлиц с липучкой - `полиэстер; нейлон`;
  - для нашивок без липучки - `полиэстер`.
- `14177451` / `Страна производства` - `Россия`.
- `179792` / `Количество предметов в упаковке` -
  `1 шт.`, `2 шт.`, `3 шт.`, `4 шт.`, `5 шт.`; петлицы = `1 шт.`.
- `378533` / `Комплектация`:
  - `шеврон на липучке N шт.`;
  - `нашивка без липучки пришивная N шт.`;
  - `неразрезанная пара петлиц на липучке 1 шт.`.
- `15001405` / `Ставка НДС` - оставить текущее/по налоговому режиму; не
  менять без отдельного финансового правила.

Поле `Фабричное производство` подтверждено в Ozon. В WB-редакторе для
проверенной карточки отдельное поле с таким названием не подтверждено, поэтому
нельзя утверждать его наличие в WB без новой проверки схемы/редактора.

## Правила упаковки и веса

Ozon указывается в миллиметрах, WB - в сантиметрах.

| Тип товара | Ozon упаковка | WB упаковка | Вес |
| --- | --- | --- | --- |
| Нарукавный шеврон | `100*100*10 мм` | `10*10*1 см` | `10 г` |
| Шеврон на кепку | `100*60*10 мм` | `10*6*1 см` | `10 г` |
| Нагрудный шеврон | `130*50*10 мм` | `13*5*1 см` | `10 г` |
| Шеврон на спину | `300*100*10 мм` | `30*10*1 см` | `30 г` |
| Петлицы, 1 товарная единица | `100*40*10 мм` | сначала `10*4*1 см`, fallback `10*5*1 см`, затем `10*6*1 см` | `10 г` |

`10 г` - текущий минимальный рабочий вес обычного изделия; `5 г`, `7 г` и
другие меньшие значения в marketplace state считать drift against passport,
если нет отдельного owner-approved исключения.

Комплекты:

- длина/ширина упаковки = максимальные длина/ширина среди изделий комплекта;
- толщина упаковки = количество физических изделий * `10 мм`;
- вес = сумма веса физических изделий.

Петлицы:

- 1 товарная единица = две неразрезанные петлицы;
- размер самих петлиц: `80*30*5 мм`;
- количество в упаковке и единиц в товаре: `1`.

## Правило для HTML-аудита

В каждом HTML-аудите карточки должен быть блок целевых параметров для пачного
заполнения:

- Ozon: название, габариты/вес, бренд, модель, ТН ВЭД, хештеги, аннотация,
  материал, размер, количество в упаковке, единиц в товаре, цвет, название
  цвета, целевая аудитория, вид выпуска, страна, количество заводских
  упаковок.
- WB: наименование, категория, 18+, артикул продавца/nmID/баркод как
  unchanged, бренд, цвет, ТНВЭД, КИЗ, описание, габариты/вес, вид декора,
  состав, страна, количество предметов, комплектация, НДС как unchanged/review.

Для каждого поля нужно показать:

- текущее значение;
- целевое значение;
- статус: `batch_fill`, `keep`, `needs_owner_review`,
  `needs_dictionary_check`, `do_not_touch`;
- короткое объяснение.

Поля, не относящиеся к шевронам/нашивкам/петлицам, в HTML не показывать.

## Owner-corrections

Если владелец исправляет значение после просмотра HTML, аудитор/оркестратор
обязан сохранить исправление в `audit.json` и новой версии HTML:

- текущее значение из snapshot/API остается в `current_state`;
- целевое значение для будущего dry-run записывается в `proposed_final_card`;
- исправление владельца записывается в `owner_review.corrections`;
- статус карточки можно перевести в `owner_review_approved_with_correction`,
  но это не разрешает apply без отдельной команды владельца.

Пример 2026-06-28: для карточки `chev_kp_chvk_pict0001` владелец исправил
целевой цвет Ozon/WB на `черный, белый`; остальные рекомендации по карточке
согласованы для будущего dry-run.

Пример 2026-07-04: для комплекта позывных `chev_kit2_pz_text0022` владелец
согласовал цвет товара `мох`, а если marketplace не принимает такое значение -
fallback `зеленый`, плюс `черный`. Dry-run Ozon заблокировал `мох` как
отсутствующее словарное значение (`ozon_color_dictionary_value_missing`).
Восстановление: в marketplace-полях `Цвет товара` / `Цвет` поставить
`зеленый, черный`, при этом `мох` оставить в названии, `Название цвета` и
описании как покупательски значимое название фона. Проверка результата:
повторный `apply-approved-cards` завершился `overall_status=ok`, финальный
`post_apply_content_verify` подтвердил готовность Ozon/WB.
