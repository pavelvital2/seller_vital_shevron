# Pricing Runbook

Дата актуализации: 2026-06-13

## Итог

Цены Ozon и WB относятся к опасным операциям. Любое изменение базовой цены,
скидки, минимальной цены, цены по акции или себестоимости выполняется только по
цепочке:

```text
read-only -> dry-run -> review -> approved -> apply -> verify -> result
```

Без явного подтверждения владельца разрешены только чтение, сверка, отчеты и
dry-run.

## Ozon

### Где смотреть в ЛК

Основной раздел:

```text
Товары и цены -> Список товаров -> Управление ценами
```

Разделы акций:

```text
Цены и акции -> Акции
Цены и акции -> Цены на товары
```

Минимальная цена для автодобавления в глобальные акции настраивается в блоке
цен. По справке Ozon, такая настройка учитывается 30 дней, затем
деактивируется. Поэтому для Vital Shevron нужен регулярный мониторинг
минимальных цен и отдельный refresh-план до истечения 30 дней.

### Поля и смысл

| Что видит владелец | API/проектное поле | Назначение |
| --- | --- | --- |
| Базовая цена / цена до скидки | `old_price` | Перечеркнутая цена или цена до скидки. |
| Цена со скидкой / текущая цена продавца | `price` | Основная текущая цена продавца. |
| Цена по акции | action-level price, в отчетах проекта `action_price` | Цена внутри конкретной акции Ozon. Не равна обычной цене товара. |
| Минимальная цена | `min_price` | Нижняя граница для автодобавления/автоскидок и проверок акций. |
| Себестоимость | отдельное поле ЛК/учета, в проекте пока не заведено | Внутренний учет маржинальности; не подменяет `min_price`. |

Важно: цена по акции управляется контуром акций Ozon, а не обычной массовой
загрузкой цен товара. Для Elastic Boosting уже есть отдельная инструкция
`data/planning/ozon_elastic_runbook.md`.

### API-first контур

Read-only:

```text
POST /v5/product/info/prices
```

Поля для сверки: `offer_id`, `product_id`, `sku`, `price`, `old_price`,
`min_price`, маркетинговые/акционные поля, если они присутствуют в ответе API.

Write после approval:

```text
POST /v1/product/import/prices
```

Перед apply обязателен fresh snapshot текущих цен и drift-check по всем строкам,
где меняются `price`, `old_price` или `min_price`.

### Минимальная цена Ozon

Рабочее правило проекта:

- не считать `min_price` постоянной настройкой без контроля;
- в read-only отчете показывать дату последней проверки и наличие `min_price`;
- для товаров с пустой/сброшенной `min_price` строить отдельный dry-run;
- refresh минимальных цен делать не позднее чем раз в 25-28 дней, чтобы не
  упираться в 30-дневную деактивацию;
- перед write повторно подтвердить актуальное правило Ozon в ЛК/API, потому что
  условия маркетплейса могут измениться.

## Wildberries

### Где смотреть в ЛК

Основной раздел:

```text
Товары и цены -> Цены и скидки
```

В этом разделе владелец видит базовую цену, скидку и цену со скидкой.

Минимальная цена и блокировка автоакций настраиваются через XLSX-действие в
разделе цен и скидок. По инструкции WB нужно скачать таблицу товаров, заполнить
поля минимальной цены/блокировки для нужных товаров и загрузить файл обратно.

### Поля и смысл

| Что видит владелец | API/проектное поле | Назначение |
| --- | --- | --- |
| Базовая цена | `price` | Цена до скидки. |
| Скидка | `discount` | Процент скидки продавца. |
| Цена со скидкой | `discountedPrice` | Расчетная/возвращаемая цена после скидки. |
| Минимальная цена | XLSX-настройка ЛК, API-поле в проекте не подтверждено | Нижняя граница только для автоакций, если текущая цена не ниже нее. |
| Себестоимость | внутренний учет проекта, не WB price API | Нужна для маржинальности и лимитов скидок. |

По инструкции WB минимальная цена и блокировка влияют на применение скидок в
автоакциях. Если текущая цена уже ниже минимальной, товар может продаваться по
текущей цене; минимальная цена не является запретом на собственноручно
установленную более низкую цену.

### API-first контур

Read-only:

```text
GET /api/v2/list/goods/filter
POST /api/v2/list/goods/filter
```

`GET` использовать для общего списка товаров с ценами. `POST` использовать для
точечной выборки по артикулам, когда нужно проверить конкретный список товаров.
Для Vital Shevron использовать WB-native идентификаторы: `nmID`, `vendorCode`,
barcode/size data. Mapping Ozon/WB не нужен для marketplace-local отчета.

Write после approval:

```text
POST /api/v2/upload/task
```

Метод меняет `price` и `discount` пачкой до 1000 товаров. Минимальную цену этим
методом не менять, пока официальный API-метод для минимальной цены не
подтвержден и не описан отдельно.

### Минимальная цена WB

Рабочее правило проекта:

- пока считать минимальную цену WB LK/XLSX-настройкой;
- не пытаться записывать ее через текущий `upload/task`, потому что в
  используемой схеме проекта есть только `nmID`, `price`, `discount`;
- до автоматизации сделать отдельный read-only/LK research: скачать шаблон,
  зафиксировать названия колонок и проверить, есть ли официальный API;
- после подтверждения метода создать отдельный dry-run/apply контур с
  XLSX-diff, approval и verify.

## Себестоимость

Себестоимость не должна смешиваться с ценой маркетплейса.

Для Vital Shevron рабочее базовое правило:

```text
1 шеврон = 85 ₽ себестоимость
комплект из N шевронов = 85 ₽ * N
```

Весь ассортимент Ozon и WB в проекте считается шевронами или комплектами
шевронов. Если карточка является комплектом, маржинальность нужно считать от
количества штук в комплекте, а не от одной карточки как одной единицы
себестоимости.

Рабочая схема продаж Vital Shevron:

```text
Ozon: FBO
Wildberries: FBW
```

Для расчетов минимальной цены не использовать FBS-логистику, если владелец
отдельно не подтвердил, что конкретная операция относится к FBS.

Для проекта ее нужно хранить как отдельный внутренний слой:

```text
data/catalog/unified/
data/catalog/mapping/
future internal cost/margin table
```

До создания отдельной таблицы себестоимости нельзя автоматически рассчитывать
минимальные цены по марже. Можно только показывать, что поле отсутствует или не
подтверждено.

## Минимальная цена по марже

Внутренний целевой порог за один шеврон:

```text
target_net = себестоимость + желаемая чистая прибыль + бюджет продвижения
```

Текущие базовые сценарии владельца:

| Сценарий | Себестоимость | Чистая прибыль | Продвижение | Target net за 1 шт. | Маржа после себестоимости и продвижения |
| --- | ---: | ---: | ---: | ---: | ---: |
| profit_85_ads_20 | 85 ₽ | 85 ₽ | 20 ₽ | 190 ₽ | 44.7% |
| profit_60_ads_25 | 85 ₽ | 60 ₽ | 25 ₽ | 170 ₽ | 35.3% |

Дополнительные рабочие сценарии для тестирования:

| Сценарий | Себестоимость | Чистая прибыль | Продвижение | Target net за 1 шт. | Маржа после себестоимости и продвижения | Когда использовать |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| balanced_70_ads_25 | 85 ₽ | 70 ₽ | 25 ₽ | 180 ₽ | 38.9% | Базовый компромисс между маржей и продвижением. |
| profit_85_ads_30 | 85 ₽ | 85 ₽ | 30 ₽ | 200 ₽ | 42.5% | Если нужно больше рекламного запаса без снижения прибыли. |
| growth_45_ads_35 | 85 ₽ | 45 ₽ | 35 ₽ | 165 ₽ | 27.3% | Временный рост/распродажа, не постоянный минимум. |
| premium_100_ads_20 | 85 ₽ | 100 ₽ | 20 ₽ | 205 ₽ | 48.8% | Товары с хорошим спросом, отзывами или уникальностью. |

Target net - это не обязательно цена на витрине. Для настоящей минимальной цены
Ozon/WB нужно добавить расходы маркетплейса:

```text
min_sale_price = (target_net + fixed_marketplace_costs) /
                 (1 - variable_marketplace_rate)
```

Где:

- `fixed_marketplace_costs` - логистика, обработка, хранение, возвраты и другие
  фиксированные расходы на заказ;
- `variable_marketplace_rate` - комиссия площадки, эквайринг, налог от выручки
  и другие процентные расходы;
- точные значения нужно брать из калькуляторов Ozon/WB или финансовых отчетов,
  потому что они зависят от категории, модели продаж, габаритов и тарифов.

### Обратный расчет от суммы на руки

Если владелец задает сумму, которую нужно получить на руки уже после
продвижения, сначала нужно вернуть рекламный расход:

```text
required_after_marketplace = desired_cash_after_ads + ad_spend
```

Затем рассчитать минимальную цену продажи:

```text
min_sale_price = (required_after_marketplace + fixed_marketplace_costs) /
                 (1 - variable_marketplace_rate)
```

Пример без отдельного фиксированного расхода, когда все удержания Ozon/WB уже
сведены в эффективный процент:

| На руки после рекламы | Реклама | Нужно после удержаний площадки | 20% удержаний | 25% | 30% | 35% |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 145 ₽ | 20 ₽ | 165 ₽ | 207 ₽ | 220 ₽ | 236 ₽ | 254 ₽ |
| 145 ₽ | 25 ₽ | 170 ₽ | 213 ₽ | 227 ₽ | 243 ₽ | 262 ₽ |
| 170 ₽ | 20 ₽ | 190 ₽ | 238 ₽ | 254 ₽ | 272 ₽ | 293 ₽ |
| 170 ₽ | 25 ₽ | 195 ₽ | 244 ₽ | 260 ₽ | 279 ₽ | 300 ₽ |

Если есть фиксированные расходы площадки, например логистика/обработка, цена
растет сильнее. Пример:

| На руки после рекламы | Реклама | 25% + 40 ₽ | 30% + 50 ₽ | 35% + 60 ₽ |
| ---: | ---: | ---: | ---: | ---: |
| 145 ₽ | 20 ₽ | 274 ₽ | 308 ₽ | 347 ₽ |
| 145 ₽ | 25 ₽ | 280 ₽ | 315 ₽ | 354 ₽ |
| 170 ₽ | 20 ₽ | 307 ₽ | 343 ₽ | 385 ₽ |
| 170 ₽ | 25 ₽ | 314 ₽ | 350 ₽ | 393 ₽ |

## Следующий технический шаг

Создать read-only отчет `pricing-status`, который по Ozon и WB показывает:

- идентификаторы товара в native marketplace формате;
- базовую цену;
- цену со скидкой;
- цену по акции, если применимо;
- минимальную цену, если она доступна;
- себестоимость, если она будет подключена во внутренней таблице;
- предупреждения: пустая минимальная цена, Ozon min-price refresh нужен,
  текущая WB цена ниже минимальной, товар участвует в акции без маржинального
  лимита.

Telegram-вывод отчетов по ценам, маржинальности, марже и расходам строить по
общему стандарту `data/planning/chat_report_templates.md`.
