# Seller SKU Rules

Дата: 2026-06-13.

## Итог

Правило описывает формирование новых артикулов продавца для магазина Vital
Shevron. Оно применяется к новым товарам и к будущему плану унификации
артикулов, но само по себе не является разрешением менять уже существующие
`offer_id` Ozon или `vendorCode` WB.

Изменение существующих артикулов продавца на Ozon/WB остается опасной
операцией и выполняется только через:

```text
read-only -> mapping draft -> owner review -> approved mapping ->
dry-run rename plan -> owner approval -> apply -> verify -> result
```

Источник правила: вложенный файл владельца `префиксы артикулов.txt`, получен
2026-06-13.

## Общий формат

Базовый формат:

```text
<product_prefix>[_<type_prefix>][_kitN][_structure_prefix]_<content_prefix><number>
```

Правила записи:

- использовать нижний латинский регистр;
- разделять смысловые блоки символом `_`;
- не использовать пробелы и кириллицу;
- номер писать четырьмя цифрами, например `0001`;
- `text` или `pict` пишется слитно с номером: `text0001`, `pict0001`;
- перед созданием нового префикса, которого нет в этой инструкции, обновить
  этот документ и `data/planning/recommendations_index.md`, если изменение
  влияет на каталог или автоматизацию.

## 1. Тип товара

Обязательный первый блок для всех шевронов и нашивок:

| Префикс | Значение |
| --- | --- |
| `nash` | нашивка |
| `chev` | шеврон |

Если в ассортименте появится другая продукция, для нее нужно добавить новый
первый префикс отдельным обновлением правила.

## 2. Назначение, размещение и комплекты

Следующие блоки добавляются после типа товара, если применимы:

| Префикс | Значение |
| --- | --- |
| `pz` | позывной |
| `back` | на спину |
| `kitN` | комплект из `N` штук: `kit2`, `kit3`, `kit4`, `kit5` и т.д. |

Если позывной продается комплектом, использовать связку:

```text
pz_kitN
```

Пример:

```text
chev_pz_kit2_text0001
```

## 3. Принадлежность к структуре

Если у товара есть принадлежность к структуре, добавить соответствующий
префикс. Если принадлежности нет, блок пропустить.

| Префикс | Значение |
| --- | --- |
| `mvd` | МВД |
| `fsin` | ФСИН |
| `rg` | Росгвардия |
| `fso` | ФСО |
| `fsb` | ФСБ |
| `fssp` | ФССП |

Нагрудные и спинные варианты также должны иметь префикс структуры, если
принадлежность есть.

Пример:

```text
chev_back_mvd_text0001
```

## 4. Содержание

Обязательный блок перед номером:

| Префикс | Значение |
| --- | --- |
| `text` | текст |
| `pict` | картинка / изображение |

## 5. Номер

Номер добавляется после `text` или `pict` без дополнительного `_`.

Формат:

```text
0001
0002
0003
```

До отдельного уточнения владельца рабочее правило такое: номер должен быть
уникален внутри полного набора префиксов, чтобы один и тот же seller SKU не
использовался повторно для разных товаров.

Перед созданием нового артикула нужно проверить:

- нет ли такого seller SKU в Ozon catalog;
- нет ли такого seller SKU в WB catalog;
- нет ли такого seller SKU в `data/catalog/unified/` или будущем планe
  унификации.

## Примеры владельца

```text
nash_kit2_rg_pict0001
chev_pz_kit2_text0001
nash_mvd_pict0001
chev_back_mvd_text0001
```

## Проверка перед использованием

Перед добавлением нового товара:

1. Выбрать `product_prefix`: `nash` или `chev`.
2. Добавить назначение: `pz`, `back`, `kitN`, если применимо.
3. Добавить структуру: `mvd`, `fsin`, `rg`, `fso`, `fsb`, `fssp`, если
   применимо.
4. Добавить содержание: `text` или `pict`.
5. Выбрать следующий свободный четырехзначный номер.
6. Проверить уникальность в Ozon, WB и внутреннем unified/mapping слое.
7. Для cross-marketplace товара связать новый артикул с mapping/common product
   record.

## Открытые уточнения

В исходном файле не указано, в каком именно разрезе вести счетчик `0001`:

- глобально по всему магазину;
- отдельно по `product_prefix`;
- отдельно по полной комбинации префиксов.

До уточнения владельца использовать наиболее безопасный вариант: уникальность
по полному seller SKU и запрет повторного использования одного SKU для разных
товаров.
