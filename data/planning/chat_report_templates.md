# Telegram Report Templates

Дата: 2026-06-13.

## Краткий вывод

Для Vital Shevron Telegram-сообщение является основным экраном отчета для
владельца. Файл отчета все равно должен сохраняться, но в чат нужно выводить
достаточный, структурированный и не перегруженный summary, чтобы его можно было
читать с ноутбука или телефона без открытия файла.

Файл полного отчета прикреплять или указывать внизу Telegram-сообщения после
основного вывода.

## Отправка файлов в рабочий топик

Для отправки файлов в рабочий Telegram-топик `seller_vital_shevron` использовать
бота `@Koara_2_vps_bot`, потому что он состоит в группе `Koara_codex`.
Не использовать для этого `Vital_Shevron_Manager_bot`: он может не видеть чат и
Telegram вернет `Bad Request: chat not found`.

Параметры топика:

```text
topic_url: https://t.me/c/3683440820/42336
chat_id: -1003683440820
message_thread_id: 42336
```

Токен брать из внешнего файла проекта Telegram-агента, не выводить и не
сохранять в репозиторий:

```text
/home/pavel/projects/telegram-ai-agent/.env
TELEGRAM_BOT_TOKEN
```

Шаблон отправки файла:

```bash
TOKEN="$(python3 - <<'PY'
from pathlib import Path
for line in Path('/home/pavel/projects/telegram-ai-agent/.env').read_text(encoding='utf-8').splitlines():
    s = line.strip()
    if s.startswith('TELEGRAM_BOT_TOKEN='):
        print(s.split('=', 1)[1].strip().strip('"').strip("'"))
        break
PY
)"

curl -sS -X POST "https://api.telegram.org/bot${TOKEN}/sendDocument" \
  -F "chat_id=-1003683440820" \
  -F "message_thread_id=42336" \
  -F "document=@/abs/path/to/file.html" \
  -F "caption=Файл для проверки"
```

Проверенный пример: 2026-06-28 файл `chev_nr_bpla_pict0028.html` отправлен в
этот топик через `@Koara_2_vps_bot`, Telegram вернул `message_id=72852`.

## Общий стандарт Telegram-отчета

### Обязательная структура

```text
<Название отчета>

Итог: <1-3 строки с главным выводом>

Период: <период или "на дату">
Маркетплейс: <Ozon/WB/all>
Режим: <read-only/dry-run/apply/verify>
Run ID: <run_id>

Ключевые цифры:
- <метрика>: <значение>
- <метрика>: <значение>

Что важно:
- <находка/риск/изменение>
- <находка/риск/изменение>

Что предлагаю:
- <действие 1>
- <действие 2>

Ограничения:
- <что не подтверждено, чего нет в источниках, где fallback>

Следующий шаг:
<конкретное действие или фраза согласования>

Файл отчета:
<attached file или короткий путь к файлу>
```

### Правила компактности

- В чат выводить все важное для решения, но не весь построчный файл.
- Для длинных списков показывать топ/анти-топ `5-10` строк и количество
  остальных строк в файле.
- Не перегружать ссылками: обычно достаточно `run_id`, периода, источника и
  прикрепленного файла.
- Не вставлять raw JSON, длинные CSV, stack trace, cookies, headers, токены,
  storage state и закрытые данные.
- Для write-related отчетов всегда писать, что уже сделано, что только
  предлагается, и требуется ли согласование владельца.
- Если отчет переделывается, новую версию нужно снова отправить в чат, а не
  только обновить файл.
- Если файл невозможно прикрепить через Telegram в текущей среде, внизу
  сообщения указать локальный путь к сохраненному файлу и прямо написать, что
  прикрепление не выполнено.
- Telegram-сводку отправлять реальным многострочным текстом. Нельзя передавать
  отчет как одну строку с литеральными `\n`: Telegram-клиент может показать
  такой отчет одной строкой, что делает согласование неудобным. После отправки
  длинного owner-facing отчета нужно визуально оценить формат вывода в чате;
  если переносы не применились, сразу переотправить отчет корректным
  многострочным текстом.

### Режимы и формулировки

Read-only:

```text
Режим: read-only. Изменений в магазинах не выполнял.
```

Dry-run:

```text
Режим: dry-run. Это расчет/план, изменения не применялись.
```

Apply:

```text
Режим: apply. Применял только согласованные строки из approved package.
```

Verify:

```text
Режим: verify. Проверил результат после apply.
```

Blocked:

```text
Статус: blocked. Я не могу подтвердить результат, потому что <причина>.
```

## Отчет по карточке товара

Для покарточной работы Telegram-вывод является основным экраном владельца.
Файл полного отчета сохранять и прикреплять, но в чат выводить достаточно
полную картину для решения без открытия файла.

В чате не указывать источники, API-методы, raw paths и прочую техническую
информацию. Эти данные остаются в файле отчета.

## Отчет по акциям WB

Для WB акций и схемы скидок в Telegram-сводке обязательно показывать не только
количество строк к изменению, но и бизнес-причины изменения скидки.

```text
Отчет по акциям WB

Итог: <например: найдено 276 строк к снижению скидки; upload не выполнялся>.

Схема: <scheme>
Режим: <dry-run/apply/verify>
Run ID: <run_id>

Сводка:
- всего товаров: <n>
- в активных акциях: <n>
- вне активных акций: <n>
- изменить скидку: <n>
- снизить скидку: <n>
- повысить скидку: <n>
- не менять: <n>

Причины изменения скидки:
- превышение порога <threshold>%: <n>
- участие в акции с меньшей требуемой скидкой: <n>
- отсутствие в активных акциях: <n>

Пояснение:
- превышение порога: скидка до порога выше разрешенного значения, применяется fallback;
- участие в акции с меньшей требуемой скидкой: товар в акции, но нужная скидка ниже текущей;
- отсутствие в акциях: товар не найден в активных акциях; если текущая скидка уже fallback, строка не попадает в payload.

Файл отчета:
<attached file/path>
```

## Ежедневный отчет

Ежедневный отчет строится за одну дату: предыдущий календарный день по
`Europe/Moscow`, период `00:00-23:59`. Все ключевые параметры показывать сразу
по двум маркетплейсам: Ozon и WB. Текущие состояния, которые не относятся к
прошедшему дню, помечать как "на текущий момент".

Если перед отправкой ежедневного отчета видно, что отчет неполный из-за
недоступного ЛК, слетевшей сессии или ошибки LK/CDP fallback, агент сначала
предлагает владельцу восстановить подключение к ЛК и пересобрать отчет.
Неполный отчет отправляется только после подтверждения владельца, что он нужен
сейчас в текущем виде, либо если восстановление ЛК невозможно в текущем
цикле. В таком случае в чате нужно явно указать блоки `не подтверждено` и
причину.

```text
Ежедневный отчет

Итог: <главный статус дня: все спокойно / есть риски / нужны действия>.

Дата отчета: <today YYYY-MM-DD>
Период данных: <yesterday YYYY-MM-DD>, 00:00-23:59 MSK

Run ID: <run_id>

Статус систем:
- Ozon API: <ok/warning/error>
- WB API: <ok/warning/error>
```
