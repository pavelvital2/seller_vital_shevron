# Ревизия проекта 2026-08-01

## Итог

Завершён согласованный пакет из пяти направлений: карточный pipeline, runtime
approvals, ежедневный отчёт, dry-run `Цены и маржа` для Ozon/WB и восстановление
частичных inbox-операций. В рамках разработки marketplace write не выполнялся.

## Реализовано

1. Карточки:
   - TaskRegistry pre-validator Layer 2;
   - актуальные поля упаковки Ozon/WB;
   - независимые media plans без общего WB fallback;
   - lifecycle и история CardWorkItem;
   - закрытие локальных слоёв после `apply -> verify`.
2. Runtime:
   - единый список file/runtime approvals;
   - `approve/reject/apply/verify` через Job Worker;
   - закрытие RunManifest и защита от повторного apply.
3. Ежедневный отчёт:
   - точная дневная метрика отмен Ozon с помеченным fallback;
   - фильтр отзывов/вопросов по MSK и пагинация;
   - completeness/reconciliation расходов;
   - regression tests на 2026-07-22.
4. Цены и маржа:
   - Ozon и WB в отдельных меню;
   - срезы 15/30 дней;
   - себестоимость/маржа на физическое изделие и `pack_qty`;
   - минимальная, скидочная и базовая цены;
   - stock/action gates;
   - только dry-run, apply отсутствует.
5. Inbox:
   - стабильные action-id и verified receipts;
   - повтор только неподтвержденного хвоста;
   - подтвержденные ответы и mark-read не повторяются;
   - автоматический cleanup при нулевом хвосте.
6. Scheduled routing:
   - автоматические отчёты направляются в `Vital Shevron Manager`, owner chat
     `867144591`, без topic/thread;
   - технический Codex topic не используется scheduled-задачами.

## Остаточные ограничения

- обе кнопки `Цены и маржа` пока только рассчитывают и сохраняют dry-run;
  изменение цен требует отдельного проекта apply/verify;
- WB action gate зависит от доступности read-only LK snapshot; при недоступном
  ЛК отчёт обязан показывать `not_confirmed`;
- action receipts подтверждают результат конкретного write-ответа. Fresh
  read-only verify остаётся обязательным бизнес-контролем после inbox apply.
