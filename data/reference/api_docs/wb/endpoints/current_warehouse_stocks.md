# WB Current Warehouse Stocks

Дата проверки: 2026-07-17.

## Endpoint

```text
POST https://seller-analytics-api.wildberries.ru/api/analytics/v1/stocks-report/wb-warehouses
```

Официальная документация:

```text
https://dev.wildberries.ru/openapi/analytics
```

Назначение: текущие остатки по размерам и складам WB. Данные обновляются раз в
30 минут. Одна строка ответа соответствует одному `chrtId` на одном складе.

## Request

JSON body:

- `nmIds` - до 1000 артикулов WB;
- `chrtIds` - фильтр размеров;
- `limit` - до 250000 строк;
- `offset` - пагинация.

Требуется Personal или Service token категории Analytics. Лимит: один запрос
раз в 20 секунд, до трех запросов в минуту.

## Response

Основные поля `data.items[]`:

- `nmId`;
- `chrtId`;
- `warehouseId`;
- `warehouseName`;
- `regionName`;
- `quantity`;
- `inWayToClient`;
- `inWayFromClient`.

## Подтвержденное расхождение 2026-07-18

Во время незавершенной FBW-приемки `statusID=4` поле `inWayFromClient` может
временно включать товары входящей поставки, несмотря на подпись ЛК `В пути от
покупателя`.

Проверка по Электростали:

- всего `inWayFromClient=401`;
- `313` единиц совпали по всем `23 nmId` поставки `40815358`;
- еще `3` единицы тех же `nmId` находились в `inWayToClient`;
- `313 + 3 = 316`, что точно совпало с `acceptedQuantity=316` этой поставки;
- оставшиеся `88` единиц не относятся к этой поставке и требуют отдельной
  транзакционной сверки; исторический срез ниже исключает их трактовку как
  массовые возвраты/невыкупы.

Следствие: при `statusID=4` нельзя интерпретировать весь
`inWayFromClient` как возвраты покупателей. Нужна сверка `nmId` с FBW Supply
API и повторная проверка после завершения приемки.

Дополнительная историческая сверка:

- 2026-07-17 21:30: `quantity=383`, `inWayFromClient=22`,
  `inWayToClient=1`, сумма состояний `406`;
- 2026-07-18: `quantity=9`, `inWayFromClient=401`, `inWayToClient=3`, сумма
  состояний `413`.

При почти неизменной общей товарной массе WB перенес около `379` единиц в
`inWayFromClient`. Это подтверждает техническую переклассификацию состояния,
а не `401` фактический возврат покупателями. Точная причина не подтверждена;
временная остановка Электростали и незавершенная приемка могут быть связаны,
но остаются гипотезой до данных WB на уровне движения единиц.

Для общего текущего остатка товара проект суммирует `quantity` по всем размерам
и складам одного `nmId`.
